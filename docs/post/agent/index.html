Add Shade Tree Grove to an agent.

Install one verified Rust binary, start its embedded-Arti Proxy, then give that route to one agent process.

Research preview. v0.4.1 is the current patched binary agent distribution. There is no repo-maintained public v4 access profile; an operator must admit your leaf and supply the matching discovery values.

1. Download and verify

The installer detects the platform, downloads the matching v0.4.1 -live binary and checksum, verifies both digest and filename, and installs into ~/.local/bin. The binary includes the Proxy, RLN prover, and Arti; the agent machine needs neither Node.js nor a system Tor daemon.

curl -q -fsSL --proto '=https' --proto-redir '=https' \
  https://raw.githubusercontent.com/dmarzzz/shade-tree-node/main/scripts/install.sh \
  | SHADE_TREE_VERSION=v0.4.1 sh
shade-tree --version

Intel macOS has no prebuilt live tunnel in v0.4.1. The macOS binary is checksummed and attested but not yet notarized. The Rust installation guide lists published targets, manual checksum and attestation verification, and source builds.

2. Create an identity and get admitted

Ask one Grove operator for the exact rate tier, an invited, staked, or paid admission path, the Elder Tree onion and its raw 64-hex Canopy signer, and the matching membership input.

read -r SHADE_TREE_LIMIT
shade-tree enroll --limit "$SHADE_TREE_LIMIT" --out identity.json > public-leaf.txt

identity.json contains the member secret and stays local. Send only public-leaf.txt through the operator's admission process. For invited access, wait for the operator to confirm that leaf in the root its nodes verify and save the matching members.json.

There is no public profile to substitute here. Do not use the retired Sepolia records or invent values. If you do not have an operator, ask for operator or onboarding help in GitHub Discussions; never post identity.json, a member secret, or a Proxy token.

3. Start the embedded-Arti Proxy

Create an unpredictable Proxy token in the terminal that will run the Proxy:

(umask 077; set -C; shade-tree proxy-token > proxy-token.txt)
IFS= read -r SHADE_TREE_PROXY_TOKEN < proxy-token.txt
export SHADE_TREE_PROXY_TOKEN

Then load the operator-supplied discovery pair and start invited access on loopback:

read -r SHADE_TREE_BOOTNODE_ONION
read -r SHADE_TREE_DIR_SIGNER
shade-tree proxy \
  --bootnode-onion "$SHADE_TREE_BOOTNODE_ONION" \
  --signer "$SHADE_TREE_DIR_SIGNER" \
  --identity identity.json \
  --members members.json \
  --listen 127.0.0.1:8118

The signer and Elder onion are one trust-pinned pair; take both from the same operator. Staked and paid profiles use that operator's contract and RPC values instead of members.json. Keep the token file only for this running Proxy.

4. Launch the agent

IFS= read -r SHADE_TREE_PROXY_TOKEN < proxy-token.txt
export SHADE_TREE_PROXY_TOKEN
shade-tree run -- your-agent

Run this in a second terminal. The wrapper authenticates the Proxy before launch and gives proxy variables only to its child. For Hermes, replace your-agent with hermes. Software that ignores proxy variables must be pointed at the authenticated URL documented in the full guide.

Current boundary

The Proxy accepts HTTP CONNECT and the node permits target port 443. TLS stays between the agent and destination. The serving node still sees the target hostname, timing, lifetime, and traffic volume. This research preview has not had the trusted setup and independent audit required for a production release.
